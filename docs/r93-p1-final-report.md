## 2. 配置

d24_c1 dense（288M active + Engram 220M，K=40k/V=41,280，seq 8192）；2^21 tok/step；
LR 8e-4、WSD warmup 30 / decay-start 0.9 / min 0.1；z-loss 1e-4；EMA 0.995 每步；
grad-clip 1.0；seed 1234；数据 `p2_climbmix_40k` 扩到 8.568B tokens（单 epoch 0.934，无重复）；
环境：private image t141（torch 2.14.1+cu130 / triton 3.8.0 / tilelang 0.1.15）+ production kernel + E0。

## 4. 与参考的对比（诚实版）

- **对 P0b 短跑曲线外推的 0.89**：差 +0.177。外推错在把短预算（0.2–0.6B、高 LR 短跑终值）的
  β=0.154 用到 8B；实际长跑 β 衰减到 0.06–0.08，曲线显著变平。
- **对仓库内 nanochat 插值线（iso-FLOPs，C=1.38e19 → bpb 0.94）**：我们 +0.126 更差。
  ⚠️ 该线来自 nanochat 自己的 val 集，与我们的 ClimbMix-val panel 不同源，跨项目 bpb 只能粗略可比；
  但在同一口径下我们的小预算点（0.2B/0.4B）明显好于该线外推值，8B 点反而更差 → 说明该线斜率
  （-0.2）与我们的实际曲线形状不一致，**"等算力超越 nanochat"这一轮没有得到证明**。
- **结论**：P1 是一次干净、完整的 8B 长跑实验，但没有实现"性价比超越 nanochat"的目标；
  目标 0.718 更远，需要模型规模/数据/算力的量级提升。

## 5. 教训（已写入各专题文档）

1. **短预算曲线不能外推长预算**：0.2–0.6B 的 β=0.154 外推到 8B 给了 0.89，实际 1.066。
   以后长跑前必须用 1B/2B 的"长跑锚点"实测曲线，而不是外推。
2. **LR 探针**（4B ckpt + 4 臂 × 0.2B 恒定 LR，¥12/4h）是便宜且决定性的诊断：
   本次证明 8e-4 不是瓶颈，省掉了"重启换 LR"的 ¥60–110 冤枉钱。
3. **EMA** 实测 −0.0042 bpb、开销≈0；**z-loss v2 快速路径** +0.46% 步时（旧路径 +17.7%）。
4. 工程教训：no-GPU 实例 CPU 被限流（重分词慢 10×，必须放 GPU 实例）；实例间传输同区可达
   ~300MB/s（跨区仅 ~11MB/s）；ckpt 默认不含优化器状态（需 `--save-optimizer`）。

## 6. 下一步建议

- **P2 之前先锚定**：用目标配置跑 1B/2B 两个短锚点（约 ¥15–30），拿到真实长跑曲线再决定预算；
- 若目标是 0.718：按当前证据需要"更大模型（600–730M active）× 更多 tokens（10–20B）+ KD"，
  成本估计 **¥300–600+**，且应先用 2–3 个锚点校准收益；
- 若目标是"性价比叙事"：可如实报告本轮"在 ~¥128/35h 的 8B 长跑里做到 1.066 raw / 1.062 EMA，
  MFU 51.6%"，并把 LR/EMA/z-loss 的方法论收获作为资产，等更大预算再冲绝对 bpb。
- 剩余资产：6B/8B/EMA ckpt、8.568B 语料（在实例数据盘）、全部曲线与 eval 数据（本地 `runs/r93/p1/`）。
