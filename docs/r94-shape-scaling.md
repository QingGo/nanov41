# V4 深度/宽度缩放关系 与 我们量级的形状选择（2026-11-18）

## 1. 两个 V4 配置点

| | 激活参数 | 总参数 | 层数 L | hidden C | C/L | head 占比* |
|---|---:|---:|---:|---:|---:|---:|
| V4-Flash | 13B | 284B | 43 | 4096 | 95.3 | 1.9%（129,280×4096 / 49B 对比口径） |
| V4-Pro | 49B | 1.6T | 61 | 7168 | 117.5 | 1.9%（129,280×7168 / 49B） |

来源：llm-infra-atlas 对 DeepSeek-V4 技术报告（arXiv 2606.19348）§2.2 的整理 / HF transformers deepseek_v4 配置。

## 2. 两点推出的缩放关系（以激活参数 N 计）

```
N ratio = 3.769,  L ratio = 1.419,  C ratio = 1.750
L ∝ N^0.264        C ∝ N^0.422        (2·0.422 + 0.264 = 1.107，略大于 dense 的 1.0 → V4 是 MoE，激活参数随 C 增长略快)
C/L ∝ N^0.158      （13B 时 95.3 → 49B 时 117.5：越大越"宽"）
```

**重要 caveat**：只有 2 个点、跨度 3.8×，且 V4-Pro 的形状与 V3（61 层/7168）相同——V4 的两点更像"MoE 容量扩张 + Flash 重新设计"，
不是干净的形状定律；外推 45× 到我们量级只能当"先验"，不能当定论。C=4096/7168 也受 TP/kernel 约束。

## 3. 外推到我们的量级（N_act = 288M，V=41,280，我们的每层系数 k≈9.77·C² + head V·C）

用 V4 的 **C/L 形状律**（C/L = 95.3·(N/13B)^0.158），再按我们的参数账本解 L、C、FFN h：

| N_act | C/L（V4 外推） | 解出 L | C | dense FFN h | head 占 N_act |
|---:|---:|---:|---:|---:|---:|
| **0.288B（我们）** | **52.1** | **≈21** | **≈1090** | ≈2520 | 15.6% |
| 0.6B（P2 候选） | 58.6 | ≈25 | ≈1480 | ≈3780 | 10.2% |
| 1.0B（P2 候选） | 63.5 | ≈29 | ≈1820 | ≈4890 | 7.5% |

**我们现行 d24_c1（L=24, C=1024, h=2304, C/L=42.7）与该外推（21×1090，C/L=52）只差 ~15%**，
且差异方向是"我们更窄更深"——这与我们 **V=41,280（40k tokenizer）导致 head 占比高达 15.6%**（V4 只有 1.9%）
的修正方向一致：head 随 C 线性增长，我们加宽更贵，所以最优形状应比 V4 律更偏"窄深"一点。→ **d24_c1 的选择被 V4 律支持**。

若强行用 dense 自洽指数（2b+a=1、b=0.42 → a=0.16）外推：L≈23.4、C≈823；但代入我们的参数账本只得到 N_act≈189M（V4 每层系数比我们大），
说明该口径不适用，应以 C/L 形状律 + 自身账本为准。

## 4. 对"高宽比"讨论的含义

- **d24_c1 是 V4 律下的合理点**（21×1090 的近邻）；d16w_c2（16×1280，C/L=80）偏"宽浅"，d32n_alt（32×768，C/L=24）偏"窄深"、在 V4 律外推范围之外。
- 但 MobileLLM（ICLR'24）在 125M/350M 上实测"深而窄"（30–42 层，C/L≈20–30）优于同时代同尺寸模型——**两条证据线冲突**，
  且我们规模（288M/8B tokens）比 V4（13B–1.6T）小 2–4 个数量级、比 MobileLLM 的 token 预算小 2 个数量级。
- **唯一可行裁决**：2×2 锚点实验（0.3B tokens/臂，¥4.3/臂）：
  {d24_c1, 21×1088(V4-law), d32n_alt} × {mHC on, mHC off}；看交互项，判据 Δbpb≥0.01。
- 若未来上 P2：按 V4 律 0.6B active → ~25 层 × 1480；1B active → ~29 层 × 1820；但要注意 head 占比与 kernel 形状整数约束。
